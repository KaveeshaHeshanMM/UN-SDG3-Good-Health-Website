Profile Page

Technical Description

The User Profile page combines HTML, CSS, and JavaScript to create an attractive and interactive profile page. The HTML organizes content into clear sections using navigation, header, and multiple container elements to separate different types of profile information. The CSS styling creates a dark-themed design that's easy to read, with light text on dark backgrounds and highlighted accent colors for important elements. The profile information is neatly centered on the page within a container that stands out from the background. Subtle animations make the page feel dynamic when it loads. Interactive elements change appearance when users hover over them, providing visual feedback. The navigation menu uses flexible spacing to arrange items evenly across the top of the page. The JavaScript adds functionality to the volunteer scheduling feature, displaying time slot options when a date is selected and capturing the user's choice when they click a specific time.

Accessibility

This profile page lacks important accessibility features that would help all users access its content. The page needs proper color contrast - the yellow sign-in button on dark background might be hard to see for some people. Missing alt text on social media icons prevents screen readers from describing these elements. The form fields don't have proper labels connected to inputs, making them difficult for assistive technology users. The page lacks proper heading structure and keyboard navigation support. Time slot selection relies only on visual cues with no keyboard accessibility. Adding ARIA labels, improving color contrast, and ensuring keyboard navigation would make this page more accessible to everyone.

Volunteer Page

Technical Description

This sitemap page uses SVG (Scalable Vector Graphics) to create an interactive visual representation of the website structure. The HTML file contains an SVG element that serves as a canvas where the sitemap is drawn using shapes and lines. The sitemap design shows site navigation with rectangular boxes representing different website pages, connected by lines with arrows showing relationships between pages. Each box is made clickable by wrapping it in an anchor tag, allowing users to navigate directly to that page. The CSS styling makes the sitemap both attractive and interactive. When users hover over a page box, it changes color and slightly enlarges, providing visual feedback. The connecting lines feature animated drawing effects created using stroke-dasharray and stroke-dashoffset properties, making them appear to draw themselves when the page loads. Text labels inside each box identify the page name, with styling that ensures readability against the background. The animations for both boxes and text create a staggered entrance effect, with boxes appearing first followed by their labels, giving the sitemap a dynamic feel when loaded. The responsive design ensures the sitemap displays properly across different screen sizes by using relative measurements.

Accessibility

The sitemap page has several accessibility issues that need to be addressed. Currently, it lacks proper text alternatives for the SVG elements, making it difficult for screen reader users to understand the website structure. The page should include ARIA labels or descriptions for the SVG elements and proper alt text for interactive elements. The color contrast between text and background should be improved to meet accessibility standards. Additionally, keyboard navigation support is missing - users should be able to tab through the sitemap nodes. The page also needs semantic HTML elements to provide structure and context for assistive technologies, rather than relying solely on visual presentation through the graphic elements.

Content Page

Technical Description

This fitness-focused webpage combines structure and styling to create an engaging user experience. The page is built with a dark theme using a black background with yellow accent colors for contrast and visual appeal. The structure uses semantic HTML tags including navigation bars, content sections, and a footer. The main navigation at the top remains fixed as users scroll, while a secondary internal navigation provides quick links to related content. CSS styling creates visual hierarchy with gradient backgrounds, hover effects, and animations. Interactive elements like buttons have subtle scaling effects when hovered, enhancing user feedback. The page also implements responsive design principles with percentage-based widths. JavaScript functionality powers the "go to top" button, which appears only when users scroll down the page. This button provides smooth scrolling back to the top through the window.scrollTo method with "smooth" behavior parameter. The combined techniques create a modern, responsive fitness resource with intuitive navigation and visual engagement.

Accessibility

While the current implementation has some accessible elements like semantic HTML structure and descriptive alt text for images, there are several accessibility improvements needed. The page lacks proper heading hierarchy, with only h1 and h2 elements used. Focus indicators for keyboard navigation aren't clearly defined. Color contrast between the yellow text and dark background should be verified for readability. The page would benefit from ARIA landmarks and labels to improve screen reader navigation. Interactive elements like buttons need keyboard accessibility improvements. Adding skip navigation links would help keyboard users bypass repetitive content. These enhancements would make the fitness website more accessible to users with disabilities.

Challenges and Lessons Learned

During development, I faced challenges with incorrect arrow mappings on the sitemap and calendar features. These navigation elements weren't properly connecting to their intended destinations, causing user confusion. Through troubleshooting, I learned valuable animation techniques that enhanced the visual feedback of the interface. After identifying the mapping issues, I successfully corrected the arrow connections, ensuring they properly linked to the sitemap and calendar sections. This experience improved my debugging skills and understanding of how navigation elements should function cohesively within a website. The process taught me the importance of testing interactive elements thoroughly before deployment.

Compliance

My website follows basic Janet rules for student web publishing. I've used proper HTML structure with correct DOCTYPE and meta tags. The navigation is clear with labeled links to help users find information easily. For accessibility, I've added alt text to images and created a readable layout, though I need to improve keyboard navigation. The sitemap provides a visual guide to the website structure with animated connections between pages. I've included a Privacy Notice link in the footer to address data protection requirements. The responsive design works on different screen sizes by using flexible layouts and percentages instead of fixed widths. While I've made a good start with these compliance elements, I recognize there are areas to improve, particularly with keyboard accessibility and WCAG standards, which I will continue to develop as I learn more.
